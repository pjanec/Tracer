## Issues Encountered and Resolutions

### 1. Validator rejects `SessionId = ""`
**Issue:** `AnnotationEndpoints.ValidateCreate` used `string.IsNullOrWhiteSpace(dto.SessionId)` which rejected empty string. The batch instructions call for `SessionId = ""` annotations for the round-trip test.

**Root Cause:** `AggregationOrchestrator` passes `request.SessionId ?? ""` to `AnnotationsExporter.ExportAsync` when building by TimeRange. So annotations needing to be exported must have `SessionId = ""`.

**Fix:** Changed validator check from `IsNullOrWhiteSpace` to `is null`. All 13 existing `AnnotationEndpointsTests` still pass.

### 2. `WaitForBundleLoadedAsync` timeout
**Issue:** The helper checked `json.Contains(accepted.BundleId)` but the `bundleId` from `BundleBuildAcceptedDto` is the directory name (ULID generated by `BundleBuildService`), while `CurrentBundleDto.BundleId` is the MANIFEST's bundle ID (another ULID generated by `ManifestBuilder`).

**Fix:** Changed `WaitForBundleLoadedAsync` to check for any non-null bundle loaded (presence of `"bundleId"` key in JSON and not `"null"` response), since the viewer is started with the specific bundle path.

### 3. `TriggerEvalEndpoints` needs `SessionQueryService` session to exist
**Issue:** `TriggerEvalEndpoints.HandleAsync` calls `sessions.GetAsync(sessionId)` which returns null (→ 404) if no `system.session_start` event exists in DuckDB.

**Fix:** Push a `system.session_start` event with `{"sessionId":"s1"}` payload in `InitializeAsync` before pushing trigger events.

## Developer Insights

### Issues Encountered
1. **Missing `ViewType` field**: `CreateSavedViewDto.ViewType` is `required string` — batch instructions didn't mention it. Added `"Timeline"` as the test value.
2. **Wrong query params for TriggerEval**: Batch instructions specified `fromNs`/`toNs` (nanoseconds), but the actual endpoint uses `from`/`to` as `DateTimeOffset`. Fixed by building URLs with ISO 8601 formatted DateTimeOffset values and URI encoding.
3. **Validator too strict**: Empty SessionId needed for time-range annotation export — validator now allows it.
4. **BundleId mismatch**: Service-generated bundle ID ≠ manifest bundle ID. `WaitForBundleLoadedAsync` updated to check for any bundle loaded.
5. **SessionQueryService returns null**: TriggerEval endpoint returns 404 when session not found — fixed by pushing a session_start event in test initialization.

### Weak Points Spotted
- The `BundleBuildService` generates a ULID for the build, and `ManifestBuilder` generates another ULID for the manifest. These two IDs are not linked, which can cause confusion for consumers who try to correlate them (as happened in this test).
- `AggregationOrchestrator` uses `sessionId = ""` for time-range annotation export — this is an implicit contract that's easy to violate. A named constant or dedicated "all sessions" export method would be clearer.

### Design Decisions Beyond Spec
- `TriggerEvalIntegrationTests` uses a static `_nextId` counter to ensure unique trigger IDs per test run, avoiding cross-test data contamination in the shared DuckDB instance.
- The `BuildTriggerUrl` helper centralizes URL construction with proper URI encoding for DateTimeOffset parameters.
